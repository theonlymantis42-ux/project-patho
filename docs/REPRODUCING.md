# Reproducing the current workflows

The notebooks run in Google Colab and load a saved model. They are inference and review tools, not a one-click model-training package.

## Whole-slide review notebook

Use `Project_Patho_Process_and_Review.ipynb` for the full-grid review workflow.

1. Open the notebook in Google Colab.
2. Make sure you have access to the private Google Drive folder used by the notebook.
3. Place the intended checkpoint at `MyDrive/Pathology_Project/my_cancer_model.h5`, or edit `MODEL_PATH` to point to the correct file. Do not silently substitute `model.keras`; the notebooks and evaluation records refer to different checkpoint histories.
4. Upload an authorized, de-identified whole-slide image to Drive. The notebook accepts SVS, NDPI, and pyramidal TIFF inputs through OpenSlide.
5. Run the cells from top to bottom. The notebook installs `openslide-python==1.4.7`, `openslide-bin==4.0.1.2`, and SciPy, then loads TensorFlow from the Colab runtime.
6. Choose the Drive slide and start processing. The notebook writes a review report and intermediate outputs to the Drive project folder.

The notebook checks slide MPP metadata and uses a nominal PCam target scale. Verify the scanner metadata and model's actual training scale before interpreting a research run. A complete grid scan still leaves heuristic-filtered supports unscored. The HTML report contains an overview, not the original-resolution slide.

## Bounded Colab notebook

`Project_Patho_Paper2_Colab_Processing.ipynb` is a separate bounded workflow. Its default public CMU-1-Small-Region skin slide is a technical smoke test of file processing and display. It is not a cancer-detection evaluation. Its default candidate cap is 2,000, and it writes a timestamped run folder with configuration, manifest, CSV predictions, and a dashboard-result JSON file.

Do not use the public sample to estimate accuracy. For a research run, use only data you are authorized to process, confirm the pixel scale, and record the exact input and checkpoint hashes.

## Analysis scripts: current limitations

A clean clone is not yet sufficient to reproduce every analysis in the repository:

- `reproduce_analysis.py` expects `predictions.csv` and `plan.json` beside the script. The referenced `plan.json` is not currently present at the repository root.
- `evaluate_internal_no_overlap.py` imports `prepare_pcam.py` and checks for `evaluate_internal.py`; those files are not currently present at the repository root.
- The repository does not yet provide one pinned environment file covering the notebooks and analysis scripts.
- Some paper figures and the archived manuscript package are stored as exports rather than being generated by a single documented command.

For those reasons, the scripts are useful records of the analysis workflow but should not yet be described as a fully reproducible clean-clone pipeline.

## Before sharing a run

Keep a copy of the run's configuration and manifest alongside its predictions. Record the checkpoint hash, source-data version, preprocessing, threshold, software versions, coverage, and exclusions. Never publish patient-identifying information or a slide image unless authorization and de-identification have been confirmed.
